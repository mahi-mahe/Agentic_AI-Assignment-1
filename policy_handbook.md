# Student Support Policy Handbook — Demonstration Copy

**Document status:** Sample policy for software demonstration only. It is not an approved institutional policy. Replace it with the institution's signed handbook before production use.

## Fee payment and portal downtime
1. Students should retain the payment reference, timestamp, and a screenshot or other evidence of a failed transaction.
2. A student should raise a fee-support ticket before the published due date when the payment portal fails.
3. Portal failure does **not automatically extend** the payment deadline.
4. Any extension or permission to pay on the next working day requires written confirmation from the Accounts Office.
5. The support agent must not promise a waiver, extension, or acceptance of late payment unless the policy source explicitly authorizes it.

## Fee records and privacy
1. Fee and scholarship details are confidential student information.
2. The agent should request a student ID before retrieving an individual record.
3. The agent must not disclose one student's record to another student or an unverified third party.
4. The agent should return only the fields needed to answer the question.

## Scholarships
1. Scholarship statuses in the demonstration database are sample values.
2. "Approved", "Under Review", "Not Eligible", "Pending Documents", and "Rejected" are status labels used by this demo.
3. The agent must not infer eligibility or promise disbursement dates from a status alone.
4. Students should contact the Scholarship Office for official eligibility, appeal, and disbursement decisions.

## Exams, timetable and events
1. The database schedule is a demonstration schedule.
2. The agent should quote the semester and date/time/venue exactly as stored.
3. The calendar contains sample/provisional events. Entries marked as sample are not official institutional announcements.
4. If a date, venue, holiday, event, or policy is absent, the agent must say that the available source does not confirm it.

## Support requests
1. A support ticket can be created for a known student ID and a clearly stated issue.
2. The agent should report the ticket ID returned by the ticket tool.
3. If a tool fails, the agent must say that ticket creation could not be confirmed.
